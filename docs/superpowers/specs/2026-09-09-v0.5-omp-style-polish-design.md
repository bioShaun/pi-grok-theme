# v0.5 — omp-style polish design

- **Status:** design only — implementation gated on user review of this document
- **Date:** 2026-09-09
- **Baseline:** package `0.4.1` on `main` @ `50d5b70`
- **Target version:** `0.5.0` (one CHANGELOG entry when R4 lands; work may ship as sequential PRs)

This document specifies four release slices (R1–R4) that move pi-grok-theme toward Oh My Pi (omp) visual and distribution polish **without** depending on omp-only upstream tokens or breaking Pi theme schema validation.

---

## 1. Goal

Deliver a vars-first, omp-flavored chrome experience on top of Adaptive Chrome (0.4.x):

1. **Palette as source of truth** — nearly all theme colors alias shared `vars` (titanium-style), with three committed Pi theme JSON files generated from one palette + overlays.
2. **Footer visual upgrade** — omp-like presets, glyph density, and named separators, persisted beside existing settings, without abandoning single-line fitting.
3. **Richer git + path info** — OSC 8 hyperlink on the path segment; staged / dirty / untracked counts colored through existing Pi semantic tokens.
4. **Dual distribution** — from the same vars, emit omp-compatible theme JSON (extra `pythonMode` + `statusLine*` tokens) in a separate tree so Pi themes stay schema-clean.

## 2. Non-goals (explicitly deferred)

| Deferred item | Reason |
| --- | --- |
| Tokens-per-second (`tok/s`) metric | Not in 0.5 scope; revisit after footer density stabilizes |
| Reactive auto light/dark theme pair | omp-style pair switching needs host appearance signals we do not own yet |
| Upstream Pi `symbols` section | Not in Pi schema; stay extension-local via `glyphs.ts` |
| Fake / invent `statusLine*` tokens on **Pi** themes | Would fail Pi schema validation; omp extras live only under the omp export tree |
| Native omp status-line host APIs | We remain a Pi extension footer; we do not require running under omp |
| Product code changes in this commit | This file is design-only |

## 3. Current state snapshot (0.4.1)

### Themes

- Load path (package.json `pi.themes`): `themes/grok-build.json`, `themes/grok-build-coding.json`, `themes/grok-build-day.json`.
- Each file already has a `vars` block (surfaces, fg/muted/dim, border, blue/cyan/amber/purple/green/red; coding/day also define `orange`).
- Most `colors.*` entries already reference var names; a few intentional empties remain (`text: ""` = terminal default). Themes are hand-maintained JSON — no generator yet.
- Chrome colors at runtime come only through `chrome-theme.ts` (Pi `Theme` tokens → tones).

### Footer

- Presets: `auto` | `minimal` | `full` (`FOOTER_PRESETS` in `footer.ts`).
  - `minimal`: model + context + status only.
  - `auto` / `full`: all eligible segments; `full` additionally shows whole-turn duration when available.
- Default separator: literal `" · "` (`DEFAULT_FOOTER_CONFIG.separator`).
- Git: branch only via `getGitBranch` (`.git` dir, worktree/submodule `gitdir:` file, walk-up); **3s TTL** cache keyed by cwd. No staged/dirty/untracked counts.
- Path: plain styled cwd segment; no OSC 8.
- Glyphs: `glyphs.ts` modes `modern` | `legacy` (env `PI_GROK_LEGACY_GLYPHS`, win32 auto-detect). No nerd-font preset.

### Settings

- Path: `~/.pi/agent/pi-grok-theme.json` (`SETTINGS_FILENAME`, overridable via injected agent dir in tests).
- Schema today:
  ```json
  { "footerPreset": "auto", "showHeader": false }
  ```
- Defaults: `footerPreset: "auto"`, `showHeader: false`.
- UX: `/grok footer auto|minimal|full`, `/grok header`, persisted on change.

### Quality baseline to preserve

- `npm run typecheck` (`tsc --noEmit`)
- `npm test` (Node test runner; suite is already **99+** cases across `test/*.js`)
- Deterministic SVG previews (`scripts/render-previews.js`, fixed preview cwd)
- Git worktree / relative `gitdir` tests in `test/test.js` must keep passing

## 4. Architecture overview

```
shared palette + overlays          omp token map
        │                                │
        ▼                                ▼
 scripts/build-themes.js  ──────►  themes/*.json          (Pi load path; schema-clean)
        │                      └─►  themes/omp/*.json     (omp install path; extras OK)
        │
        ▼
 extension runtime
   settings.ts  — persist footerPreset / glyphDensity / separatorStyle / showHeader
   glyphs.ts    — unicode | nerd | ascii sets (+ capability gate for nerd)
   footer.ts    — presets, separators, OSC8 path, git counts + cache
   chrome-theme.ts — unchanged contract: tones only (success/warning/error/muted/accent/…)
```

**Module boundaries**

| Module | Owns | Must not own |
| --- | --- | --- |
| `scripts/build-themes.js` | Palette, overlays, emit Pi + omp JSON | Runtime chrome, settings I/O |
| `themes/*.json` | Committed Pi themes (source of truth for Pi install) | omp-only keys |
| `themes/omp/*.json` | Committed omp export artifacts | Being listed in `package.json` `pi.themes` |
| `settings.ts` | Load/save/migrate prefs | Rendering |
| `glyphs.ts` | Glyph vocabulary + density selection | Color / git |
| `footer.ts` | Segments, fitting, separators, OSC8, git branch+counts | Theme file generation |
| `chrome-theme.ts` | Tone → ANSI via Pi theme | New fake token names |
| `index.ts` | Wire `/grok` UX, install/dispose | Palette literals |

## 5. R1 — Foundation (vars-first themes)

### Intent

Strengthen the titanium-style vars-first palette and generate the three Pi themes from shared data so palette edits cannot drift across files. **No footer behavior change in R1.**

### Defaults (explicit)

- Generator path: `scripts/build-themes.js` (Node ESM, no new runtime dependency).
- Source modules (same script or tiny sibling JSON/JS under `scripts/theme-src/`):
  - `palette-dark.js` — shared dark vars (current `grok-build` / coding surfaces + accents).
  - `palette-day.js` — day vars (current `grok-build-day`).
  - `overlay-base.js` — color alias map for `grok-build`.
  - `overlay-coding.js` — coding deltas (e.g. `thinkingText` → purple, `orange` var, syntax/tool tweaks matching today's coding JSON).
  - `overlay-day.js` — day alias map matching today's day JSON.
- **Committed JSON remain the Pi load path.** CI / `npm test` theme-quality checks continue to read `themes/*.json` only. Developers regenerate with `node scripts/build-themes.js` (add npm script `build:themes` in R1).
- Nearly all `colors.*` values must be var references or the intentional empty string `""` for terminal default (`text`). No raw hex inside `colors` except where Pi/export already requires hex in `export.*` (export may keep hex literals derived from vars at build time).
- Expand `vars` only as needed for aliases already implied by today's files (do not invent unused decorative vars). Coding's `orange` stays coding-only unless base gains a real consumer.
- R1 acceptance: byte-stable or semantically identical theme tokens vs 0.4.1 after first generator landing (allow formatting/key-order normalization only if tests/docs updated in the same PR). Prefer preserving observable colors exactly.

### Out of scope for R1

Footer presets, separators, glyphs, OSC8, git counts, omp export tree.

## 6. R2 — Visual (footer presets, glyphs, separators)

### Presets

| New preset | Meaning | Maps from |
| --- | --- | --- |
| `minimal` | model + context + status (unchanged) | `minimal` |
| `default` | all eligible segments, responsive fitting (today's `auto`) | `auto` |
| `full` | default + whole-turn duration when available (unchanged) | `full` |

- `FooterPreset` becomes `"minimal" | "default" | "full"`.
- `FOOTER_PRESETS` lists those three only for UX/completion.
- Migration: see §8 (`auto` → `default` on load; writes never emit `auto`).

### Glyph density

| Density | Role | Default selection |
| --- | --- | --- |
| `unicode` | Today's `modern` set | **Default** for non-legacy terminals |
| `ascii` | Today's `legacy` set | Auto on win32 legacy path; or explicit |
| `nerd` | Nerd Font codepoints for branch/folder/etc. | **Opt-in only** — never auto-selected |

- Extend `glyphs.ts`: keep `GlyphSet` keys; add `NERD_GLYPHS` and `GlyphDensity = "unicode" | "nerd" | "ascii"`.
- Capability: `nerd` applies only when settings request it **and** env does not force ascii (`PI_GROK_LEGACY_GLYPHS=1` wins → ascii). Missing Nerd Font is an open risk (see §11); we still emit nerd codepoints when opted in.
- Map: existing `detectGlyphMode()` continues as capability baseline; settings `glyphDensity` overrides when set to `nerd` or `ascii`. Default persisted value: `"unicode"` (omit key ⇒ unicode, with platform legacy still forcing ascii glyphs at runtime as today unless user explicitly set `unicode` via env `PI_GROK_LEGACY_GLYPHS=0`).

**Persisted default:** `glyphDensity: "unicode"`.

### Separators

Named styles (string enum persisted as `separatorStyle`):

| Style | Literal separator | Notes |
| --- | --- | --- |
| `dot` | ` · ` | **Default** — preserves 0.4.1 look |
| `powerline-thin` | ` \uE0B1 ` (with flanking spaces trimmed per fitting rules) | Soft powerline chevron; width risk noted in §11 |
| `slash` | ` / ` | Simple omp-like slash |
| `ascii` | ` | ` | Safe ASCII pipe |

- Runtime still uses `FooterConfig.separator` as the concrete string; `separatorStyle` is the settings/UX name that resolves to that string (and optional chrome dim styling already applied today).
- Keep current default visually identical by selecting `dot`.

### Settings fields after R2

```json
{
  "footerPreset": "default",
  "showHeader": false,
  "glyphDensity": "unicode",
  "separatorStyle": "dot"
}
```

Unknown keys ignored; missing new keys use defaults above.

### `/grok footer` UX

- `/grok footer` — show current preset, glyph density, separator style, and short help.
- `/grok footer <minimal|default|full>` — set preset (persist).
- `/grok footer glyphs <unicode|nerd|ascii>` — set density (persist).
- `/grok footer sep <dot|powerline-thin|slash|ascii>` — set separator (persist).
- Tab completion lists the new tokens; unknown values warn without changing state.
- Accept legacy typed `auto` as an alias for `default` in the command parser (one release), but help text and persistence use `default` only.

## 7. R3 — Information (OSC 8 + git counts)

### OSC 8 path hyperlink

- Wrap the **path / cwd segment** display text in OSC 8 hyperlinks:
  - Start: `ESC ] 8 ; ; <file-url> BEL` (or `ST`)
  - End: `ESC ] 8 ; ; BEL`
- `file-url`: `file://` + absolute resolved cwd (encode appropriately). Soft-fail: if URL cannot be formed, render plain path (no link).
- Visible width math must ignore OSC 8 payload (same discipline as other ANSI): strip for `visibleWidth` / fitting; never count control sequences as columns.
- Preview / SVG renderer: strip OSC 8 for deterministic snapshots (no machine-local `file://` paths in committed previews — continue using the fixed preview cwd fixture).

### Git staged / dirty / untracked counts

- Extend git helpers beside `getGitBranch` (same file or `git-status.ts` if size warrants):
  - Prefer reading `git status --porcelain=v1 -b` via `child_process` with timeout, **or** equivalent filesystem-light approach if already proven in-repo; default choice: **`git status --porcelain=v1`** with `GIT_OPTIONAL_LOCKS=1`, ignore failure → no counts.
  - Parse: staged = entries with non-space in index column; dirty = worktree modified (second column); untracked = `??`.
- Display (when preset includes git and any count &gt; 0): append compact counts after branch, e.g. `⎇ main +2 ~1 ?3` (exact glyphs from active GlyphSet; ascii fallback `+` `~` `?`).
- **Colors through existing Pi tokens only** (via `chrome-theme` tones):
  - staged → `success`
  - dirty → `warning`
  - untracked → `error` (or `muted` when count is zero / omitted — zero counts are omitted entirely)
  - branch mark/name → `accent` (unchanged)
- Do **not** introduce `statusLineStaged` etc. on Pi themes.

### Cache

- Reuse the branch cache shape: `{ cwd, expiresAt, branch, staged, dirty, untracked }` with **3000 ms TTL** (same as today's branch cache).
- Invalidate on explicit footer dispose / theme reinstall paths that already clear `cachedBranch`.
- Tests: extend worktree fixtures; mock or temp repos for count parsing; ensure no flake from real user repos.

### Preset interaction

- `minimal`: still no cwd/git (unchanged).
- `default` / `full`: cwd (OSC 8) + branch + counts when available.

## 8. Settings schema migration

On `loadSettings`:

1. Read JSON; on failure → defaults (`footerPreset: "default"`, `showHeader: false`, `glyphDensity: "unicode"`, `separatorStyle: "dot"`).
2. If `footerPreset === "auto"` **or** missing/invalid → treat as `"default"`.
3. Validate enums for new fields; invalid → defaults.
4. **Write-back migration (best-effort):** if the file existed and contained `"auto"`, save the migrated object so the on-disk value becomes `"default"` (and fills new keys). If save fails, runtime still uses migrated in-memory settings.

On `saveSettings`: always write the four-field schema above; never write `auto`.

Defaults object:

```ts
{
  footerPreset: "default",
  showHeader: false,
  glyphDensity: "unicode",
  separatorStyle: "dot",
}
```

## 9. R4 — Distribution (omp-compatible export)

### Intent

From the **same** vars + overlays used in R1, emit omp-compatible theme JSON that adds:

- `pythonMode` (hex or var — default alias: `amber` / day equivalent)
- Fourteen `statusLine*` tokens required by omp (names per omp research / titanium):  
  `statusLineBg`, `statusLineSep`, `statusLineModel`, `statusLinePath`, `statusLineGitClean`, `statusLineGitDirty`, `statusLineContext`, `statusLineSpend`, `statusLineStaged`, `statusLineDirty`, `statusLineUntracked`, `statusLineOutput`, `statusLineCost`, `statusLineSubagents`

### Defaults for omp token mapping (explicit)

| omp token | Maps from (semantic) |
| --- | --- |
| `pythonMode` | `amber` |
| `statusLineBg` | `surface1` |
| `statusLineSep` | `dim` |
| `statusLineModel` | `blue` / accent |
| `statusLinePath` | `fgSecondary` |
| `statusLineGitClean` | `green` |
| `statusLineGitDirty` | `amber` |
| `statusLineContext` | `cyan` |
| `statusLineSpend` | `purple` |
| `statusLineStaged` | `green` |
| `statusLineDirty` | `amber` |
| `statusLineUntracked` | `red` |
| `statusLineOutput` | `fgSecondary` |
| `statusLineCost` | `purple` |
| `statusLineSubagents` | `cyan` |

Emit under **`themes/omp/`** (committed), e.g. `themes/omp/grok-build.json`, `…-coding.json`, `…-day.json`. Do **not** register these in `package.json` `pi.themes`.

### Docs

- README (+ zh-CN if touched in that PR): short “Install for Pi vs omp” — Pi uses `themes/*.json` via the package; omp users copy/symlink from `themes/omp/` into their omp themes directory.
- Pi schema validation in CI continues to validate **only** `themes/grok-build*.json` (non-omp).

### Out of scope

Shipping an omp package entrypoint; auto-install into `~/.omp`.

| Gate | Requirement |
| --- | --- |

- **R1:** generator round-trip or committed output matches expected overlays; `pi.themes` paths unchanged.
- **R2:** settings migration unit tests (`auto` → `default`); separator width fitting matrix still green; nerd opt-in does not activate without settings.
- **R3:** OSC8 stripped width === visible label width; cache TTL behavior; porcelain fixtures.
- **R4:** omp JSON contains the 15 extra keys; Pi JSON does not; document paths in README.

## 11. Open risks

| Risk | Mitigation |
| --- | --- |
| **Powerline / nerd glyph column width** | Fitting already uses `visibleWidth`; add explicit width tests for `powerline-thin` and nerd branch/folder marks. Document that broken fonts may mis-measure — users can switch `sep ascii` / `glyphs ascii`. |
| **OSC 8 terminal support** | Unsupported terminals typically ignore unknown OSC; still strip for width. No feature detection required in 0.5. Click behavior is terminal-dependent (documented). |
| **Nerd Font dependency** | `nerd` is opt-in only; default `unicode`. Help text states a Nerd Font is required for correct glyphs. |
| **`git status` cost** | 3s cache + `GIT_OPTIONAL_LOCKS=1`; on failure omit counts (branch-only). Avoid spawning git when `showGit` is false or preset is `minimal`. |
| **Generator drift** | CI can optionally run `build:themes` and `git diff --exit-code` on `themes/` + `themes/omp/` once R4 exists. |

## 12. Rollout

**Preferred:** sequential PRs on branch family `v0.5-*`:

1. `v0.5-r1-vars-themes` — R1 only  
2. `v0.5-r2-footer-visual` — R2 (depends on R1 only for docs links; code-independent OK)  
3. `v0.5-r3-osc8-git-counts` — R3  
4. `v0.5-r4-omp-export` — R4 + README install notes  

- Single **CHANGELOG 0.5.0** section when R4 merges (or when a final release PR cuts 0.5.0), summarizing R1–R4.
- If the total diff stays small after R1, a single PR is acceptable — **recommendation remains sequential** for reviewability and bisect.
- Version bump to `0.5.0` in `package.json` / `version.ts` on the release PR that lands R4 (or the combined PR), not on intermediate R1–R3 merges unless publishing prereleases (`0.5.0-r1`, etc.). Intermediate merges may stay at `0.4.1` package version with changelog “Unreleased” notes, **or** use prerelease tags — pick **Unreleased section until R4**, then fold into `0.5.0`.

Implementation starts only after explicit user approval of this design.
